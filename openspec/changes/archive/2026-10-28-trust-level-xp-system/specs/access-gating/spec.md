## Purpose

定义「谁能在什么条件下看到/做什么」的统一门控契约：内容可见性策略（含匿名可读与按等级受限）、受限内容的对外表现、所有内容出口的一致性，以及驱动这些判定的门控规则引擎（受控谓词与动作、能力域默认动作、求值语义、可解释性与后台可配）。目的是终结当前「可见性只有登录/不登录两态、等级门只覆盖 TL0、六个内容出口各写一套过滤」的碎片状态。

## ADDED Requirements

### Requirement: 版面可见性策略

每个版面 MUST 有一个可见性策略，取值 MUST 为 `public`（匿名可读）、`login`（需登录）、`level`（需等级 ≥ `min_level`）三者之一，MUST NOT 用多个互不相干的布尔开关拼凑。版面可见性 MUST 支持祖先继承。

帖子 MUST 可覆盖版面策略（`posts.min_level`，缺省值表示继承版面）。

#### Scenario: 匿名读取公开版面

- **WHEN** 版面可见性为 `public` 且匿名访客请求该版面的帖子列表与帖子详情
- **THEN** 系统 MUST 返回 200 并渲染内容，MUST NOT 要求登录

#### Scenario: 低等级用户读取受限版面

- **WHEN** 版面可见性为 `level`、`min_level=3`，且当前用户等级为 1
- **THEN** 该版面的受限帖子 MUST NOT 出现在列表、搜索、sitemap、RSS 与批量接口中

#### Scenario: 游客按等级 0 判定

- **WHEN** 版面可见性为 `level`、`min_level=1`，且请求来自未登录访客
- **THEN** 系统 MUST 按等级 0 判定并拒绝，MUST NOT 因为"没有等级"而放行

#### Scenario: 帖子覆盖版面策略

- **WHEN** 版面可见性为 `public`，但某帖 `min_level=2`，且访客等级为 0
- **THEN** 该帖 MUST 按受限内容处理，MUST NOT 出现在列表等聚合出口

### Requirement: 受限内容的对外表现

等级不足时：受限内容 MUST NOT 出现在任何聚合出口（列表 / 搜索 / sitemap / RSS / 批量 / 用户主页列表）；直连单篇详情 MUST 返回 403 并明确提示**所需等级**与当前等级，MUST NOT 返回 404 或以「不存在」搪塞。

（与封禁的语义不同：封禁继续沿用 404 以避免泄露账号状态；受限内容是**已知存在、明确提示门槛**的产品行为。）

#### Scenario: 直连受限帖子详情

- **WHEN** 等级 1 的用户直接请求某篇 `min_level=3` 的帖子详情
- **THEN** 系统 MUST 返回 403
- **AND** 响应 MUST 包含所需等级与当前等级，供前端渲染升级提示

#### Scenario: 受限内容不进聚合出口

- **WHEN** 用户等级低于某帖的 `min_level`
- **THEN** 该帖 MUST NOT 出现在该用户可见的任何列表、搜索、sitemap、RSS 或批量接口结果中

### Requirement: 内容出口的可见性一致性

所有内容读取出口 MUST 共用同一个可见性判定（单一谓词函数），MUST NOT 各自硬编码状态或可见性条件。出口至少包含：帖子列表、帖子详情、搜索、sitemap、RSS、批量查询。

#### Scenario: 六出口一致

- **WHEN** 一篇帖子的可见性对某访问者为「不可见」
- **THEN** 列表、详情、搜索、sitemap、RSS、批量六个出口 MUST 一致地不返回它
- **AND** 不得出现「列表里没有但 sitemap 里有」或反之的不一致

#### Scenario: 新增内容出口必须复用谓词

- **WHEN** 新增一个返回内容的接口
- **THEN** 它 MUST 调用既有可见性谓词，MUST NOT 自行拼装状态/等级过滤条件

### Requirement: 门控规则引擎的受控语法

系统 MUST 提供门控规则引擎：规则由**优先级 + 能力域 + 条件 + 动作**构成，条件 MUST 限定为固定谓词集合（等级比较、版面/标签范围、作者等级、是否作者、窗口指标、XP、账号状态类、是否含外链），动作 MUST 限定为固定枚举（`allow` / `deny` / `require_review` / `rate_limit`）。MUST NOT 提供自由文本表达式或可执行脚本。

内容可见性 MUST NOT 通过规则动作表达，MUST 只由版面策略与帖子覆盖决定（见「版面可见性策略」）。

规则写入前 MUST 校验：非法谓词/动作、未知字段、优先级冲突、永不命中的死规则 MUST 被拒绝或明确告警。

#### Scenario: 用规则表达外链门控

- **WHEN** 运营创建规则「等级 = 0 且含外链 → deny」
- **THEN** 该规则 MUST 可保存并在求值时生效，无需改代码或重启

#### Scenario: 拒绝非法规则

- **WHEN** 运营提交包含未知谓词、未知动作或空条件的规则
- **THEN** 系统 MUST 拒绝保存并给出可读的错误说明

#### Scenario: 可见性不接受规则动作

- **WHEN** 运营试图用规则动作表达"某版面仅高等级可见"
- **THEN** 系统 MUST NOT 提供此类动作，该需求 MUST 通过版面可见性策略配置

### Requirement: 每个能力域有显式默认动作

系统 MUST 为每个能力域维护一个**显式**默认动作（读内容 / 发帖 / 评论 / 外链 / 限流），无任何规则命中时 MUST 执行该域默认动作，MUST NOT 依赖隐式默认或单一全局默认。

#### Scenario: 无规则命中走域默认

- **WHEN** 外链能力域没有任何规则命中
- **THEN** 系统 MUST 执行该域配置的默认动作，并在日志中标注"默认动作"

#### Scenario: 不同域可有不同默认

- **WHEN** 读内容域默认动作为 `allow`，外链域默认动作为 `deny`
- **THEN** 两个域在无规则命中时 MUST 分别按各自默认动作处理

### Requirement: 规则求值语义为首个匹配

多规则命中时，系统 MUST 按优先级降序取**首个命中**的规则并执行其动作，MUST NOT 对所有命中规则取"最严动作"。因此 MUST 可以用高优先级规则表达例外放行。

#### Scenario: 高优先级例外放行

- **WHEN** 存在低优先级规则「等级 = 0 → deny」与高优先级规则「等级 = 0 且 is_author=true → allow」
- **THEN** 作者本人 MUST 被放行（命中高优先级规则）

### Requirement: 门控判定必须可解释

每次门控判定 MUST 记录**命中了哪条规则**（规则 id/描述）或"走了某域默认动作"，并 MUST 关联到现有 trace 链路。后台 MUST 提供「以指定用户试算」的能力，展示各规则的命中情况，且试算结果 MUST 与实际请求一致。

#### Scenario: 排查为什么被拦

- **WHEN** 某用户的请求被拒绝
- **THEN** 日志/trace 中 MUST 能查到命中的规则标识与动作
- **AND** 后台试算 MUST 对同一用户给出同样的结论

### Requirement: 门控配置后台可配且生效无需重启

规则的增删改、启用/停用、优先级调整、能力域默认动作、版面可见性策略 MUST 均可在后台完成，且变更 MUST 在无需重启进程的前提下对后续请求生效（多实例部署下 MUST 同步生效）。

#### Scenario: 停用一条规则

- **WHEN** 运营在后台把一条 `deny` 规则停用
- **THEN** 后续请求 MUST NOT 再被该规则拦截
- **AND** 多实例部署下所有实例 MUST 在同步延迟内一致
