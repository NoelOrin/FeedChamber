XP 不是一次一次加上去的计数器，而是**按行为聚合出来的结果**：

```text
total_xp = Σ(每个指标的计数 × 当前分值) + Σ(连续签到里程碑 × 奖励) + Σ(人工调整)
```

加权发生在读取时，所以删帖、取消点赞、取消精华、审核撤回都会自动扣减，改分值也立刻对
全员生效，不用回填历史。唯一写 `users.total_xp` / `trust_level` / `level_metrics` 的地方
是重算逻辑本身，所有触发点只是调用它。

## 前置条件

- 权限码 `level:manage`：XP 规则页 `/admin/xp-rules`、等级页 `/admin/levels`。
- 人工调整与员工看板在 `/admin/users/detail?id=<用户 id>` 的「成长」页。
- 全量重算也可以用 CLI：`cd app/server && go run main.go -e prod recompute-xp`。

## XP 规则

`/admin/xp-rules` →「行为指标」。指标是固定枚举，后台只能改分值、每日上限与开关。

| 指标 | 默认分值 | 每日上限 | 说明 |
|------|----------|----------|------|
| `post_approved_count` | 10 | 25 | 已通过审核的帖子（含已关闭） |
| `comment_approved_count` | 3 | 20 | 已通过的评论，不含帖子正文 |
| `likes_received_count` | 1 | 30 | 收到的赞，只算已通过的内容 |
| `favorite_received_count` | 2 | 无 | 被收藏数 |
| `featured_post_count` | 10 | 无 | 被加精的帖子数 |
| `checkin_count` | 2 | 无 | 签到天数 |

另外两个指标只在保级里用，不给 XP：`active_day_count`（活跃天数）与
`report_upheld_count`（成立举报数）。

每日上限的作用方式要理解清楚：统计按自然日分组，**先对每天计数截断到上限，再求和**。
默认「发帖 10 分、上限 25」等于一天最多靠发帖拿 25 分，第 3 篇之后当天不再增长。

## 连续签到阶梯

`/admin/xp-rules` 的「连续签到阶梯」。里程碑是「连续天数恰好等于 N 的那一天给一次奖励」，
同一条阶梯在不同时间段可以反复触发。

| 连续天数 | 奖励 |
|----------|------|
| 3 | 3 |
| 7 | 10 |
| 15 | 20 |
| 30 | 40 |
| 60 | 80 |
| 100 | 150 |

断签后连续天数从头算，已经拿过的里程碑不会因为断签被追回（它们是签到行上的历史事实）。

## 等级定义

`/admin/levels`。等级就是一张表：门槛 `min_xp`、名称、保级窗口与保级条件。

| 等级 | 默认名称 | 起始 XP | 保级窗口 | 保级条件 |
|------|----------|---------|----------|----------|
| TL0 | 新手上路 | 0 | 无 | — |
| TL1 | 基础 | 50 | 100 天 | 无额外条件 |
| TL2 | 成员 | 200 | 100 天 | 活跃 ≥ 10 天，成立举报 ≤ 5 |
| TL3 | 常客 | 500 | 100 天 | 活跃 ≥ 50 天、发帖 ≥ 10、获赞 ≥ 20、成立举报 ≤ 3 |
| TL4 | 意见领袖 | 1000 | — | 仅人工授予（`manual_only`） |

定级与保级是同一趟计算：把启用的等级按 `min_xp` 升序排好，然后从最高一级往下试——
跳过 `manual_only` 和 `min_xp` 还没到的，算一次该等级的窗口指标，第一个满足保级条件的
就是新等级，全都不满足则落到最低等级。`window_days = 0` 表示该等级没有保级条件，只看
XP 门槛。

也就是说**等级可以升也可以降**，降级是逐级下探而不是一次到底。`manual_only` 的等级
不会被自动授予；管理员手工设过的等级（用户行上 `level_manual` 标记）在重算时保持不动，
但窗口指标仍会按其当前等级刷新，后台不会显示成一排 0。

改完等级表或 XP 规则后建议手动跑一次全量重算，让存量用户立刻对齐。

## 人工调整

`/admin/users/detail?id=<id>` →「成长」→ 人工调整。每次调整是一条账本记录：
`delta`、`reason`、操作者与时间，可正可负。删掉某条记录会立刻重算，等于撤销那次加分。

同一个页面还能「手工设级」，用于授予 TL4 这类 `manual_only` 等级或临时提级。

## 签到、徽章与排行榜

签到 `POST /api/v1/checkin`，每天一次（数据库唯一索引兜底），返回连续天数、历史最大
连续天数与总签到数。签到本身不再直接加分——它只是 `checkin_count` 与里程碑的输入。

徽章在 `GET /api/v1/badges/list`，默认有三枚：首帖、连续签到 7 天、获赞 10。徽章由系统
在对应事件后评估授予，后台没有手动发放入口。

排行榜 `POST /api/v1/leaderboard/list`，`type` 三选一：

| `type` | 榜单 | 排序字段 |
|--------|------|----------|
| `points`（默认） | 经验榜 | `total_xp` |
| `checkin` | 签到榜 | `total_checkins` |
| `posts` | 发帖榜 | `post_count` |

## 重算：唯一的写入点

`Recompute` 负责把上面所有输入折算成 `total_xp`、`trust_level` 与保级指标快照。
触发点包括发帖、评论、点赞、收藏、加精、签到、审核状态变化与人工调整。它有三个入口：

| 方式 | 命令 / 接口 | 说明 |
|------|-------------|------|
| 单个用户 | 业务触发，自动 | 每次相关行为后异步刷新 |
| 全量 | `POST /api/v1/admin/trust/recompute` | 后台按钮，可重复执行 |
| 全量（CLI） | `go run main.go -e prod recompute-xp` | 输出 `recomputed N users` |

每日还有一个 24 小时 ticker 跑一次全量重算，主要处理「长期不活跃导致保级失败」的降级——
这类变化没有任何请求会触发。

因为重算只是重新聚合，**重复执行不会重复计分**。这是可以放心反复跑的原因。

## 哪些行为会回收 XP

| 行为 | 为什么 |
|------|--------|
| 删帖 / 删评论 | 软删后不再计入聚合 |
| 审核撤回或命中转待审 | 只有 `approved` 的内容计数，待审期间该条 XP 归零 |
| 取消点赞 / 取消收藏 | 指标计数直接减一 |
| 取消精华 | `featured_post_count` 依赖精华标记 |
| 删掉某条人工调整 | 调整账本少一条 |

长期不活跃会被每日全量重算判成保级失败而逐级降档。这也解释了为什么「先发满再删掉」
刷不出等级：XP 从来不是不可撤回的。

## 验证

```bash
# 1. 看某人的 XP 分解（管理员）
curl -s http://localhost:8080/api/v1/admin/users/<user_id>/xp \
  -H 'Authorization: Bearer <sid>' | jq '.data | {total_xp, trust_level, xp_metrics}'

# 2. 全量重算并观察输出
cd app/server && go run main.go -e prod recompute-xp

# 3. 排行榜三类都能取到数据
curl -s -X POST http://localhost:8080/api/v1/leaderboard/list \
  -H 'Content-Type: application/json' -d '{"type":"checkin","page":1,"page_size":10}' | jq '.data | length'
```

后台侧到 `/admin/users/detail?id=<id>` 的「成长」页，能看到累计 XP、当前等级、窗口指标
（活跃天数 / 发帖 / 获赞 / 成立举报）与逐条贡献明细。

## 常见失败

| 现象 | 原因 | 处理 |
|------|------|------|
| 改了 XP 分值，用户 XP 没变 | 规则未启用，或 `delta=0` 被跳过 | 确认规则 `enabled=true`；保存后刷新用户详情触发重算 |
| 用户等级比 XP 看起来该有的低 | 保级条件不满足（活跃天数、成立举报超限） | 看窗口指标；必要时调低门槛或改窗口 |
| 手工设的等级被改回去了 | 该等级不是 `manual_only`，且用户没有 `level_manual` 标记 | 用「手工设级」入口设置，而不是改 XP |
| 有人等级莫名掉了 | 每日全量重算判定保级失败 | 属预期；看窗口指标确认原因 |
| 排行榜空 | `type` 拼错，落到了默认榜 | 只接受 `points` / `checkin` / `posts` |
| 连续签到奖励没给 | 阶梯被禁用，或连续天数没恰好命中 | 检查 `/admin/xp-rules` 的阶梯与禁用状态 |
