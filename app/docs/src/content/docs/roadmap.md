这一页只描述**当前仓库里已经存在的东西**，不是承诺表。标为"实验性"的能力可以工作，
但接口或行为可能调整；标为"不做"的，别等。

## 已稳定

| 领域 | 覆盖 |
|------|------|
| 内容 | 版面树、帖子、嵌套评论、标签、草稿、修订历史、回收站、置顶/锁定/精华 |
| 互动 | 点赞、收藏、关注用户、拉黑、主题订阅、私信 |
| 认证 | 服务端会话、邮箱验证码、MFA（TOTP + 备份码）、OAuth 六家、OIDC SSO |
| 权限 | 61 个平台级权限码、版面级覆盖与祖先继承、用户组、API Key scope |
| 治理 | 四种审核模式、审核队列、举报、两级禁言、封号、门控规则、审计日志 |
| 成长 | XP 聚合、等级定级 + 保级、签到、徽章、三张排行榜、人工调整 |
| 站点 | 主题 token、自定义 CSS/JS/HTML、导航、首页模块、自定义页面 |
| 集成 | REST（313 path）、SSE 通知、Webhook（12 事件）、MCP Server/Client |
| 运维 | Prometheus 指标、结构化日志、traceparent、备份与恢复、sitemap/robots/RSS |

## 实验性

| 能力 | 现状 |
|------|------|
| 社区动议 | 后端与后台可用，前台入口较少 |
| 外部 MCP 审核委托 | 可用，但需要你自备 streamable HTTP 的 MCP 服务 |
| 插件 | 只有声明式元数据（安装/启用），没有代码执行扩展点 |
| 导入 Discourse | 支持四类 JSON（users/categories/topics/posts），映射规则固定 |

## 暂未实现

| 项 | 说明 |
|----|------|
| 移动端构建 | Capacitor 流程已挂起；恢复时需按 vinext 产物重新校订 |
| 界面多语言 | 站点界面只有 zh-CN；文档站是中英双语 |
| 前台首改密页 | 后端支持 `first_change_password`，前台没有独立页面（后台有） |
| 跨用户会话管理 | `/admin/sessions` 只管理当前账号的会话，不能踢其他用户 |
| 用户手动设级 UI | 接口 `POST /user/{id}/trust_level/update` 存在，后台未暴露入口 |
| 对象存储直传 | 预签名流程存在，前端仍以服务端中转为主 |

## 不打算做

| 想法 | 原因 |
|------|------|
| REST 风格 API（PUT/PATCH/DELETE） | 与"动作式接口"的约定冲突；客户端只需记住一种写方法 |
| 插件执行任意代码 | 等于开放 RCE；插件保持声明式 |
| JWT 作为主凭证 | 服务端会话"删行即失效"的语义更适合封号、改密、改角色 |
| 内嵌 NATS | KV 与事件总线的生命周期不该绑在应用进程上 |

## 怎么判断某功能是否可用

不要看这一页猜，直接查三处：

1. **路由**：`internal/router/routes_*.go` 里有没有注册
2. **端点索引**：[端点索引](/reference/endpoints/) 里有没有这个 path
3. **后台菜单**：`/admin` 侧栏里有没有入口

三者都在，才算"能用"。
