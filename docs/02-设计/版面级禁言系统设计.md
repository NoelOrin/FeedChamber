# 版面级权限管理系统设计方案

## 一、需求分析

### 当前问题
1. 现有禁言系统只支持全局禁言（`user_id` 唯一约束）
2. 无法针对特定版面（Space）进行精细化禁言管理
3. 用户可能在某些版面违规但不应被全局禁言

### 设计目标
1. 支持全局禁言和版面禁言两种粒度
2. 全局禁言优先级最高，自动覆盖版面禁言
3. 同一用户可在不同版面拥有独立的禁言状态
4. 前端管理界面支持精细化操作

## 二、数据库设计

### 2.1 扩展 `banned` 表

```sql
-- 扩展字段
ALTER TABLE banned ADD COLUMN scope VARCHAR(20) NOT NULL DEFAULT 'global';
ALTER TABLE banned ADD COLUMN space_id VARCHAR(32);

-- 索引优化
CREATE INDEX idx_banned_user_scope ON banned(user_id, scope);
CREATE INDEX idx_banned_user_space ON banned(user_id, scope, space_id);

-- 联合唯一约束（同一用户在同一 scope + space_id 下只能有一条记录）
-- 全局禁言：user_id + scope='global' + space_id IS NULL
-- 版面禁言：user_id + scope='space' + space_id = 'xxx'
CREATE UNIQUE INDEX idx_banned_unique ON banned(user_id, scope, COALESCE(space_id, ''));
```

### 2.2 新模型结构

```go
type Banned struct {
    ID          string     `gorm:"primaryKey" json:"id"`
    UserID      string     `gorm:"index;not null" json:"user_id"`
    Scope       string     `gorm:"size:20;not null;default:global" json:"scope"`  // global | space
    SpaceID     string     `gorm:"index" json:"space_id,omitempty"`               // 版面ID（scope=space时必填）
    Reason      string     `gorm:"size:500" json:"reason"`
    IsPermanent bool       `gorm:"default:false" json:"is_permanent"`
    ExpiresAt   *time.Time `json:"expires_at,omitempty"`
    CreatedBy   string     `gorm:"size:64" json:"created_by"`
    CreatedAt   time.Time  `json:"created_at"`
    UpdatedAt   time.Time  `json:"updated_at"`
}
```


## 四、业务逻辑

### 4.1 禁言检查流程

```
function isBanned(userID, spaceID):
  1. 检查全局禁言（scope='global'）
     - 如果存在且未过期 → 返回 true（全局禁言）

  2. 检查版面禁言（scope='space' AND space_id=spaceID）
     - 如果存在且未过期 → 返回 true（版面禁言）

  3. 返回 false（未禁言）
```

### 4.2 优先级规则

| 全局禁言 | 版面禁言 | 最终结果 |
|---------|---------|---------|
| ✓ | - | ❌ 禁止（全局生效） |
| ✗ | ✓ | ❌ 禁止（版面生效） |
| ✗ | ✗ | ✅ 允许 |

### 4.3 权限检查中间件

```go
func CheckBanMiddleware(spaceIDParam string) iris.Handler {
    return func(ctx iris.Context) {
        userID := getCurrentUserID(ctx)
        spaceID := ctx.Params().Get(spaceIDParam)

        // 1. 检查全局禁言
        if bannedService.IsBanned(ctx, userID, "global", "") {
            pkg.Fail(ctx, pkg.FORBIDDEN, "您已被全局禁言")
            return
        }

        // 2. 检查版面禁言（如果 spaceID 存在）
        if spaceID != "" {
            if bannedService.IsBanned(ctx, userID, "space", spaceID) {
                pkg.Fail(ctx, pkg.FORBIDDEN, "您在该版面已被禁言")
                return
            }
        }

        ctx.Next()
    }
}
```

```sql
-- 迁移脚本：为现有记录补充默认值
UPDATE banned SET scope = 'global', space_id = NULL WHERE scope IS NULL;

-- 验证数据完整性
SELECT user_id, scope, space_id, COUNT(*)
FROM banned
GROUP BY user_id, scope, space_id
HAVING COUNT(*) > 1;
```

## 八、测试用例

### 8.1 全局禁言测试
- 用户被全局禁言后，所有版面禁止发帖
- 全局禁言过期后自动解除
- 全局禁言不影响版面禁言记录

### 8.2 版面禁言测试
- 用户在版面A被禁言，版面B可正常发帖
- 版面禁言到期后自动解除
- 同一用户可在多个版面被禁言

### 8.3 优先级测试
- 全局禁言 + 版面禁言同时存在，以全局为准
- 解除全局禁言后，版面禁言仍然生效

### 8.4 并发测试
- 多管理员同时操作同一用户禁言
- 禁言检查与发帖操作并发
